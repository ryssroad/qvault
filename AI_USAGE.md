# AI usage

QVault was built by one person (Road, `ryssroad`) working with several AI tools. This file records
what each tool did, what stayed human, and how the AI output was checked. It is part of the entry for
the **AI-Native** award.

## Roles at a glance

| Tool | Used for |
|---|---|
| **Claude** (claude.ai, Claude Opus 5.5; part of v2 written with Claude Fable 5.2) | Research of the fest and of QoreChain, threat model, design, almost all code, tests, docs, cover image, video replay renderer |
| **Claude Code** (on the author's Mac) | Ran the testnet bring-up: deploy, funding, first ML-DSA-87 withdrawal; diagnosed a Foundry receipt-parsing failure |
| **Codex** | Ran the recorded v2 demo scenario through the dashboard and checked the recording |
| **Gemini** | Early brainstorm of build ideas for the fest |
| **Human** | Choice of project and scope, every decision on direction, all testnet operations with real keys, review of every change, submission |

## How the work went

**1. Choosing what to build.** Gemini proposed four ideas (a limit-bound AI agent, a sealed-bid
auction, a vault with a post-quantum check, a quick-start scanner). Claude critiqued them against the
QoreChain docs: the auction let the organiser decrypt bids at any time, and the vault idea allowed
small ECDSA-only withdrawals — exactly what the Q-Day Drill attacker would take first. The author
chose the vault, with the rule *no value moves on a classical signature alone*.

**2. Finding the real interfaces.** The fest pages did not document the `pqcVerify` precompile.
Claude cloned `qorechain-core` and read `contracts/interfaces/IQorePQC.sol` and
`docs/EVM_PRECOMPILES.md`, which gave the ABI of `0x0A01` / `0x0A02` and two security rules that
shaped the contract: a registered key is only trustworthy with `possessionProven`, and an inactive
precompile answers with empty data, so decoding must fail closed. It then read the SDK sources and
the official workshop repo to get the hybrid-signing and EVM-window flow right.

**3. v1 contract and tests.** Claude wrote `QVault.sol` and 19 Foundry tests against precompile
mocks, written from the threat model: an attacker holding the owner's secp256k1 key, replay across
vaults and chains, recipient tampering, a copied public key without proof of possession, an inactive
precompile.

**4. Testnet bring-up.** Neither Claude nor its shell could reach the QoreChain endpoints (blocked by
its network proxy), so every on-chain step ran on the author's machine. Claude checked through the
desktop app's browser that the PQC precompiles were active on testnet before anything was deployed.
Claude Code ran the deployment sequence and found that `forge create` reports a successful deploy as
failed, because QoreChain receipts carry a field (`feePayer`) that Foundry cannot parse. Claude
replaced the step with an ethers-based deploy script.

**5. v2: timelock and guardian.** Claude wrote `QVaultV2.sol` (instant budget, timelock, guardian
veto) with 21 tests, including the bound "a thief holding the owner's PQ key gets at most one day's
budget", and the guardian agent, whose decision logic is a pure function with unit tests. The author
ran the scenario on testnet; every step matched the expected balances.

**6. Dashboard and video.** Claude built the local dashboard and signer (keys never reach the page),
added session recording, and wrote a replay renderer that turns a recorded session into video scenes
with the real page in headless Chrome. Codex executed the recorded demo run.

## What stayed human

- The decision to enter, the choice of track and of the project, and the scope cuts.
- Every testnet transaction: the keys were generated by local scripts on the author's machine and
  were never pasted into any AI chat.
- Review of each change before it was committed, and every commit.
- The Q-Day Drill registration and the drill-day transaction.

## How AI output was checked

- **Tests first:** 40 Foundry tests and 7 client tests, run on every change.
- **The chain as the judge:** v1 and v2 were both exercised on testnet, with transaction hashes in
  the README; the guardian log records each decision with its tx hash.
- **An ABI test** compares the client's hand-written ABI with the compiled contract.
- **Second opinion:** a different model (Codex) operated the system from its UI, independently of
  the model that wrote it.

## Where the AI was wrong or blind

Recorded because these are the useful part:

- The first deploy instructions used `forge script`, which simulates locally where the QoreChain
  precompiles do not exist, so the constructor would have reverted. Caught before running.
- The `forge create` receipt bug was not anticipated; Claude Code found it on the live network.
- The first dashboard had no button to close the EVM window, although the server supported it.
- In the recorded demo the guardian cancelled one operation faster than the 1-second snapshots, so the
  video shows that step through the event feeds rather than the queue table — nothing was drawn
  that the recording does not contain.
